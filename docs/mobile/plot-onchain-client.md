# Cliente móvil PLOT

La lectura pública de mercados se activa desde la pestaña PLOT. El modo de simulación es independiente, usa AsyncStorage con su propia clave y no realiza transacciones. El saldo y las posiciones de ejemplo no son evidencia de devnet.

La opción «Consultar mercados» abre el modo PLOT y permite iniciar sesión con wallet, leer cuenta y mercados, crear una compra de prueba y preparar, firmar o reconciliar predicciones y cobros. Para operar necesita un servidor con sesión, lectura finalizada y sponsor montados; no considera confirmados los datos ausentes. `PlotSessionClient` usa el desafío SIWS existente, valida origen, wallet y vencimiento antes de firmar y requiere un almacenamiento seguro inyectado para el token. El login existente puede crear una cuenta y bono legacy; ese saldo no es PLOT. `PlotAccountClient` acepta una sesión inyectada y rechaza cuentas de otra wallet. `PlotIntentController` requiere un almacenamiento, API y firmante inyectados; el identificador de almacenamiento debe ser único por origen y wallet. No guardar el bearer ni transacciones firmadas en ese almacenamiento. La clave de idempotencia se registra antes de la solicitud. Si se pierde la respuesta de preparación, se reutiliza esa clave. Si el envío es ambiguo, sólo se reconcilia la misma intención; no se vuelve a firmar ni enviar.

`PlotWalletSigner` verifica que la wallet conectada sea la esperada y firmante requerida, que la firma sea válida y que el mensaje no cambie. El adaptador MWA de sponsor se incorporó en este checkout y valida la cuenta firmante por separado del fee payer. La disponibilidad física de firma de mensajes debe probarse por wallet y dispositivo. La identidad del mercado debe venir de la lectura confiable del backend como hex minúsculo de 32 bytes; el móvil no la deriva del ID de Twitch ni ofrece editarla. El servidor debe volver a validar sesión, vínculo de wallet, permisos, identidad on-chain, cuentas, secuencia y mensaje, y consultar el estado finalizado. Una lectura `confirming` o importes nulos no habilitan cobro. Para firmar hay que compilar con `EXPO_PUBLIC_PLOT_PROGRAM_ID`, `EXPO_PUBLIC_PLOT_MINT` y `EXPO_PUBLIC_PLOT_NETWORK=devnet`; el modo `localnet` requiere además `EXPO_PUBLIC_LOCAL_GATEWAY=1` y es sólo para pruebas. El cliente compara programa, mint, PDAs, cuentas, instrucción y argumentos con la solicitud antes de firmar. La configuración no demuestra por sí sola el genesis RPC; el servidor debe verificarlo. La pantalla conectada es `PlotReal`; `PlotAccountView` es una pieza inyectable adicional.

Pruebas locales: `npx tsx --test tests/plot-mobile*.test.ts`, `npm --prefix mobile run check`, `npm --prefix mobile run build:android`. El recorrido de simulación Android está en `mobile/scripts/plot-fixture-e2e.py` y requiere un emulador aislado con el APK instalado y `ANDROID_SERIAL` definido. La prueba usa sólo fixtures. Para comprobar lectura HTTP real contra el servidor de fixtures, usar `PLOT_READ_URL=<url-portless> npx tsx mobile/scripts/check-plot-read.ts`.

Para validar el contrato de intenciones sin fondos ni RPC, ejecutar `PLOT_SPONSOR_CHECKOUT=<checkout-sponsor> portless plot-mobile-intents ./node_modules/.bin/tsx scripts/plot-mobile-intent-e2e.ts`. Este harness monta el router real del checkout indicado con una sesión, transacción, servicio y firma efímeros simulados. Prueba la recuperación tras una respuesta ambigua y no demuestra ejecución en Solana.

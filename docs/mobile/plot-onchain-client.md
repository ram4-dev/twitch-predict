# Cliente móvil PLOT

La lectura pública de mercados se activa desde la pestaña PLOT. El modo de simulación es independiente, usa AsyncStorage con su propia clave y no realiza transacciones. El saldo y las posiciones de ejemplo no son evidencia de devnet.

La capa autenticada está preparada para integración, pero no está conectada a la navegación: el móvil todavía no dispone de una sesión Plot ligada a una wallet y el servidor aún debe montar los endpoints y el constructor verificado. `PlotAccountClient` acepta una sesión inyectada y rechaza cuentas de otra wallet. `PlotIntentController` requiere un almacenamiento, API y firmante inyectados; el identificador de almacenamiento debe ser único por origen y wallet. No guardar el bearer ni transacciones firmadas en ese almacenamiento. La clave de idempotencia se registra antes de la solicitud. Si se pierde la respuesta de preparación, se reutiliza esa clave. Si el envío es ambiguo, sólo se reconcilia la misma intención; no se vuelve a firmar ni enviar.

`PlotWalletSigner` verifica que la wallet conectada sea la esperada y firmante requerida, que la firma sea válida y que el mensaje no cambie. El adaptador MWA corregido vive en el frente sponsor; no conectar el adaptador anterior que presupone que el usuario es fee payer. El servidor debe validar sesión, permisos, cuentas, secuencia y mensaje, y consultar el estado finalizado. Una lectura `confirming` o importes nulos no habilitan cobro. La interfaz `PlotAccountView` es una pieza inyectable, no una pantalla de producción conectada.

Pruebas locales: `npx tsx --test tests/plot-mobile*.test.ts`, `npm --prefix mobile run check`, `npm --prefix mobile run build:android`. El recorrido de simulación Android está en `mobile/scripts/plot-fixture-e2e.py` y requiere un emulador aislado con el APK instalado y `ANDROID_SERIAL` definido. La prueba usa sólo fixtures. Para comprobar lectura HTTP real contra el servidor de fixtures, usar `PLOT_READ_URL=<url-portless> npx tsx mobile/scripts/check-plot-read.ts`.
